# Design decisions (grill-me session, 2026-11-26)

Input for `/speckit-constitution` and `/speckit-specify`. Guiding principle: **ultra minimal – nothing that is not needed.**

## Context
- Test project for part 3 of the Medium series "European Cloud Alternatives".
- Same minimal stack on Azure (reference), then STACKIT, IONOS, Scaleway.
- Each provider is tested for roughly a day, then torn down. The app is a demo only; where (and whether) it runs permanently for the family is decided at the end of the series.

## Repository & branching
- Public GitHub repository. No real values (domain, subscription/tenant ID) committed; local `.tfvars` is gitignored. GitHub secret scanning + push protection enabled.
- `main` = Azure reference. Must work end-to-end and be tagged (`azure-tested`) before any other provider starts.
- Each European provider branches **from `main`** (star topology): `002-stackit`, `003-ionos`, `004-scaleway`. The diff `main..<branch>` is the migration effort.
- Provider branches add `terraform/modules/<provider>` next to `modules/azure` instead of rewriting it.
- Genuine, provider-independent bugs found later are fixed on `main` and rebased into the provider branch; provider-specific workarounds stay in the branch. Every backport goes into the test log.

## App
- Family library: shows texts (taken from PDFs). Start with a single lorem ipsum seed text; later only texts that are allowed to be published. No real family content in the repo.
- All texts are public. Login only for editing.
- One Keycloak role: `editor` (create, update, delete). No `family` role, no visibility flag.
- **Frontend:** Next.js (TypeScript), login via Auth.js with the Keycloak provider.
- **Backend:** Node.js 24 LTS, TypeScript, Fastify, `pg` with plain SQL. One table `texts` (id, title, body, updated_at), created on startup if missing. Validates Keycloak JWT (JWKS) and checks role `editor` on write requests.
- Two containers. Same hostname: Gateway routes `/api/*` to the backend, everything else to the frontend (no CORS).
- No tests.

## Infrastructure (Azure, `germanywestcentral`)
- Private subscription of the user. Owner rights assumed – verify read-only once `az` is installed. All resources in dedicated resource groups, tagged `project=eu-cloud-alternatives`.
- AKS: **one** node pool, 2 small nodes.
- PostgreSQL Flexible Server, Burstable B1ms, private access via VNet integration (delegated subnet). One server, two databases (app, keycloak).
- VNet with two subnets (AKS, database).
- ACR (Basic). GitHub Actions pushes via OIDC federation, identity has only `AcrPush`.
- Terraform: infrastructure only. **Local state** (gitignored). Pinned provider versions.

## In-cluster layer (identical on every provider)
- Deployed **manually** with Helm via `scripts/deploy.sh <provider>` / `scripts/teardown.sh <provider>` (Bash). No Argo CD, no helmfile.
- Chart versions pinned in `platform/versions.env`; provider-specific values in `platform/values/<provider>.yaml`, filled from Terraform outputs.
- Envoy Gateway (Gateway API) + cert-manager (Let's Encrypt, HTTP-01 via Gateway).
- Keycloak: official image `quay.io/keycloak`, plain Deployment (no Bitnami), realm imported from JSON, uses the managed PostgreSQL.
- Secrets: DB password generated by Terraform and stored in **Azure Key Vault** (RBAC; the Terraform user needs *Key Vault Secrets Officer*, assigned by Terraform). `scripts/deploy.sh` reads it (`az keyvault secret show`) and creates the Kubernetes Secret. The provider-specific part lives in a single `get_secret()` function. No External Secrets Operator, no CSI driver. No secrets in Git or pipeline variables.

## Dropped on purpose (record in test log)
Argo CD, external-dns, Azure DNS zone / DNS delegation, External Secrets Operator, workload identity, second node pool, remote state, monitoring stack, tests, Trivy image scanning.

## DNS
- Domain bought at Strato. App on the apex `<domain>`, Keycloak on `auth.<domain>`. Two A records set manually at Strato, pointing to the Gateway load balancer IP; changed per provider.

## Public & reusable (hard requirement)
- The repo is public so readers can compare the providers themselves, and it must be usable as a template for their own projects.
- **No family or project data**: no PDFs, no real texts, no personal details. Seed content is lorem ipsum only.
- **No passwords, keys, IDs or personal values** in Git: domain, subscription/tenant ID, emails, Keycloak users/passwords all come from local, gitignored config (with a committed `*.example` file).
- Everything generic and configurable: app name, domain, resource name prefix, Keycloak realm/client names. No hard-coded references to the author's setup.
- Initial Keycloak admin and editor user credentials are generated or supplied locally, never committed.

## CI/CD
- GitHub Actions on push to `main`: build both images, push to ACR (OIDC). No image scanning (Trivy dropped). The pipeline never talks to the cluster.

## Docs (English)
- `README.md` – deploy and teardown.
- `docs/test-log-azure.md` – kept up to date during the work (what, how: Terraform/CLI/portal, hidden prerequisites, agent mistakes, time, surprises, final cost).
- `docs/production-readiness-checklist.md` – stage 2, check only.

## Rules
- No `terraform apply/destroy` or cost-creating `az` command without explicit OK.
- Expected monthly cost before creating anything; budget alert reminder before first apply.
- Least privilege for the pipeline identity. Pin all versions.

## Open points
- Domain: known, kept out of Git on purpose (local gitignored config only; docs use `<domain>`).
- Verify Owner rights and vCPU quota in `germanywestcentral` (read-only).
- Install local tools: az, terraform, kubectl, helm, gh, docker.
- Cost estimate (to be given in the plan).
